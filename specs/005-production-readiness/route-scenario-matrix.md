# Route-to-Scenario Traceability Matrix

**Spec**: `005-production-readiness`  
**Inventory date**: 2026-10-07  
**Gate**: This matrix and executable red BDD/contract tests precede application implementation. A mapped test target is not passing evidence until its status is updated with a test run/artifact.

## Scenario and Evidence Keys

BDD files are planned under `specs/005-production-readiness/bdd/`. Contract checks are planned under `tests/contract/production-readiness-routes.test.ts`; API operations additionally require route/database integration checks where noted. Browser journeys use Playwright under `tests/e2e/production-readiness/`. Existing test names are listed only where they provide relevant baseline evidence; the current tests do not yet prove the complete spec contract.

| Key         | Planned scenario / outcome                                                                                                                                                                                                              |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CAT-01..06  | Active catalog and offering filters; empty catalog; service details; unknown/inactive service; navigation and accessible responsive discovery.                                                                                          |
| BOOK-01..08 | Availability query and duration; invalid/past/out-of-hours/blocked/capped slot; stale slot; full-interval + 60-minute conflict; concurrent collision; retry/idempotency and recoverable rejection.                                      |
| PAY-01..06  | Valid transfer pending outcome/reference/instructions; malformed/card request rejection; safe success/unknown ID; payment-intent disabled; webhook disabled; no Stripe configuration dependency.                                        |
| ADM-01..08  | Anonymous/wrong-role/expired session denied; admin dashboard/list/detail; service/media CRUD; business hours/date overrides/settings; booking cancel/reconcile; email resend; admin account management; validation/dependency recovery. |
| SEC-01..06  | Login and password reset enumeration/rate limits; shared limits across instances; spoofed proxy headers; data-deletion request/confirm single use; abuse response and recovery.                                                         |
| PRIV-01..04 | Deletion request response; valid/expired/replayed confirmation; scheduled retention purge; minimized audit outcome.                                                                                                                     |
| OPS-01..06  | Liveness/readiness and dependency degradation; startup without Stripe; worker/email failure and retry; production seed refusal; backup/restore; migration/deployment/rollback smoke and alerts.                                         |

## Branch Coverage and Approval Gates

- Every row above is mapped to scenario and test identifiers, but the existing baseline is not route-complete. New acceptance/contract targets remain pending until written and run.
- This matrix currently records the product-approved 60-minute minimum gap and half-open interval policy. The date/time-zone and lead-time policy, daily-cap treatment of terminal states, transfer TTL/reconciliation authority, idempotency-key retention, rate-limit thresholds/trusted proxy policy, PII retention, RPO/RTO, and operational owners still require the named approvals specified in `research.md` before those behaviors can be certified for release.
- Production-only drills, security scans, Lighthouse/manual WCAG review, staging and formal signoffs require real artifacts and named owners. They are explicitly not marked complete by this matrix.
